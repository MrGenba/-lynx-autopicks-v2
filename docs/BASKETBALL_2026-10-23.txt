NBA / WNBA parallel pipeline
============================

Current storage (2026-10-24): dedicated VPS PostgreSQL database `basketball`,
service lynx_hunter/basketball-db, with a persistent database volume and no public
PostgreSQL port. Dedicated PostgREST service basketball-api requires its own JWT;
anonymous access and OpenAPI discovery are disabled. Basketball collectors use
BASKETBALL_REST_URL / BASKETBALL_REST_KEY; baseball SUPABASE_* remain unchanged.
Workflow configuration uses restUrl for the same backend. No desktop runtime is
required. Original deployment used separate bk_* tables in baseball's Supabase;
the migration preserves all rows, sealed predictions, protocols and Telegram IDs.

Hourly storage check and daily compressed pg_dump on persistent /app/basketball-data,
retaining seven days after a successful verified dump. Alert at 80% disk used or
10 GiB database size; refuse backup creation below 2 GiB free. Forecasts/decisions
are never deleted by retention. Backups share the VPS: this is not an offsite copy.
Deployment operations and migration receipts live in maintenance outside the repo;
future SQL changes must be applied to the basketball VPS database, not Tipster_DB.

New fixed research variant: bk-shot-matchup-1
-----------------------------------------
The active value model remains frozen. This variant seals separate pregame player
forecasts and research-only candidates, including rejected markets, never value
alerts. First forecast per player/game; no post-result fitting or rewriting.
Uses validated shot volumes/conversion for 2P/3P/FT, separate catch-and-shoot and
pull-up categories where coherent, and residual attempts to avoid double counting.
Conversion shrinks to league priors. Expected makes/points are our estimates from
aggregate shot categories, not optical expected-field-goal data or shot coordinates.
Opportunity-based assists/rebounds use validated tracking when present; WNBA keeps
missing tracking as NULL and falls back to explicit seasonal-rate estimates.
Pace, projected minutes, usage and injury/lineup context enter through the sealed
current forecast and exposure. Opponent historical allowed 2P/3P conversion,
assisted baskets and own/opponent misses provide bounded matchup factors.
Roster-weighted player defensive ratings are team-on-court context, not isolated
defender talent or an inferred direct matchup. Missing roster coverage has no
defense adjustment. Steals, blocks, OREB/DREB, fouls and turnovers are preserved as
auditable inputs; no unsupported independent coefficient is assigned to each field.
Source rows must match identity, season/playoff scope, games and minutes, and have
been observed before prediction. Unavailable/ambiguous categories are excluded.
Adjustments blend at <=25%; targets are bounded +/-25%, variance never decreases.

Protocol bk-shot-matchup-prospective-1 is registered before future observations.
Primary test: first 200 eligible future games per league; first paired half-point
over market per player/stat, all discards included. Brier differences average within
game, then fixed-seed bootstrap games (not correlated individual props). Both 95%
upper bounds must be below zero against the contemporaneous sealed base forecast
and margin-free market. No test conclusion before 200 games; freeze the result.
No automatic promotion or bets. Existing four reviewers receive the new comparison
within their unchanged API budget. Telegram improvement notices are deduplicated.
Data glossary: https://www.nba.com/stats/help/glossary

Data
----
Initial validated history: NBA 2025/26 and 2026/27, WNBA 2026. SportsDataverse
hoopR-nba-data / wehoop-wnba-data public parquet files derived from ESPN box scores.
Checks: event/team/player IDs, scores, shot arithmetic, player/team sums and minutes
including overtime. Exhibition teams excluded by reviewed registry. Incomplete
boxes remain unavailable for training; missing values never become zero or DNP.

ESPN Core direct reader is implemented and tested against full NBA/WNBA examples.
Production returned HTTP 403 on some requests on Oct 23. Direct capture is disabled.
An authenticated server task downloads the public parquet snapshots hourly instead;
the upstream publication cadence is daily and late source updates are reported.
Do not claim live completeness merely because the collector ran successfully.

No raw optical trajectories or proprietary NBA tracking feed is implied.
Available box fields: minutes, starter/DNP, points, rebounds (off/def), assists,
steals, blocks, turnovers, fouls, FGM/FGA, 3PM/3PA, FTM/FTA.

Advanced and tracking aggregates (added Oct 23)
---------------------------------------------
Public SportsDataverse release assets, independently published from NBA/WNBA stats:
https://github.com/sportsdataverse/sportsdataverse-data/releases/tag/nba_stats_leaguedash
https://github.com/sportsdataverse/sportsdataverse-data/releases/tag/wnba_stats_leaguedash
https://www.nba.com/stats/help/glossary
https://stats.wnba.com/players/advanced/
The VPS could download the current Parquet assets. Direct NBA website access was
denied (403); it is not retried. No paid feeds or extra credentials are involved.

Both leagues: base, advanced, defense, miscellaneous, scoring and usage datasets.
NBA additionally: passing (including potential assists), rebounding opportunities,
possessions/touches, drives, catch-and-shoot, pull-ups, shot efficiency, rim defense,
speed/distance, elbow/post/paint touches. These are season aggregates, not optical
coordinates or player-game tracking. WNBA has no tracking assets in this source;
absence is recorded explicitly, never replaced with zeroes or NBA measurements.

Each dataset preserves provider-native field names/units, season type and per-mode.
The provider's Totals label does not mean every field is a count (MIN in the advanced
table is a per-game value). Consumers must interpret the official field definitions.
Ranks and duplicated identity columns are omitted to limit database growth.
Keep provider player IDs alongside canonical ESPN player IDs. Accept only an
unambiguous published crosswalk with matching name, or exact normalized name plus
team. Current-season NBA boxes fill teams missing from the current crosswalk.
Ambiguous/unmatched identities keep player_id=NULL. Conflicting duplicate source
contexts are quarantined in bk_stat_sources.detail, not merged or overwritten.
Rebound-component discrepancies have explicit quality flags. Game counts and
base total points are compared with the complete imported boxes of the same
season/type. Differences are marked, not resolved by choosing whichever is newer.

Tables: bk_stat_sources, bk_player_stat_versions, bk_player_stat_latest.
View: bk_player_advanced_current (one current source row per player/context/dataset).
The view exposes source_status and latest publication/check times; a consumer must
check these, player_id and quality. Changed observations are appended immutably;
identical content is reused. Service credentials cannot update/delete versions.
Publication time and first observation time are distinct. The provider does not
give an exact game cutoff: data_through stays NULL. New rows cannot be used as
historically available pregame evidence before their observation. All are marked
eligible_for_model=false at ingestion. The approved advanced feature integration
performs a separate versioned validation and records its result without rewriting
the original observation's ingest status.
Snapshots older than 48 hours are marked stale, even if the HTTP fetch succeeds.
Raw capture alone does not change probabilities. The model integration below
consumes only observations passing the separate validation policy.

Models
------
Experimental baseline and fixed challenger use basketball possessions, pace,
offensive/defensive efficiency, home advantage and regularization. Props use
weighted per-minute history and minutes uncertainty. Combinations are summed
within each historical game, retaining correlations. Integer lines retain pushes.

Snapshots are sealed before tip-off and never overwritten. Missing recent games
block forecasts for the affected teams. Player rosters must be recent and from
the current season; injuries and confirmed starting fives remain UNVERIFIED.
Published projections are conditional on participation, not recommended stakes.

Research includes every sealed forecast and every recorded market, including
discarded candidates. One initial observation per event/book/market/line/side/model
is retained immutably; bk_quotes is the mutable current price, never test evidence.
Final outcomes settle wins/losses/pushes; DNP is void, missing player data stays pending.

Predeclared primary comparison: first 200 paired prospective games, margin MSE,
fixed-seed paired bootstrap 95% CI. Improvement requires the whole CI below zero.
This is a claim about margin prediction only, not all props or profitability.
No automatic model promotion; a subsequent hypothesis needs a fresh test cohort.
Four OpenAI reviewers audit data, model, market and risk once daily per league.
JSON evidence paths are validated. Numeric probabilities come from the models.
Budget: at most 16 reserved calls/day; ordinary schedule uses 8. Independent key.

Advanced model and estimated-value alerts (approved Oct 23)
--------------------------------------------------------
Version bk-advanced-opportunity-1 runs alongside the two frozen models. This is a
fixed experimental candidate, not an empirically demonstrated improvement.
Gate bk-advanced-validation-1 requires matching league/season/playoff context,
unique player/provider IDs, complete box reconciliations, source publication age
<=48 h and collector age <=2 h. Every observation must precede the prediction and
tip-off. Counts, scoring arithmetic, TS/eFG and minutes units are cross-checked.
Tracking needs consistent opportunities, converted outcomes, games and minutes.
Bad tracking inputs are excluded independently; WNBA never receives invented NBA
tracking. Validated WNBA season rates provide limited assist/rebound priors instead.

The feature candidate shrinks shot conversion toward league rates (100 two-point,
75 three-point, 50 FT prior attempts) and assists/rebounds toward league conversion
with 50 prior opportunities. Usage controls the limited points adjustment weight.
Weight <=min(25%, GP/(GP+20), MIN/(MIN+600)); targets are capped at +/-30% of the
historical baseline. Minutes/pace come from the existing model. Variance is never
reduced, and historical combination covariance is retained. Team scoring shifts
use half the player point differences, normalize excessive total roster minutes,
require 65% minute coverage on both teams and are capped at 3 points per team.
Rejected or missing stats retain a labeled baseline fallback; fallback forecasts
cannot generate advanced-value alerts. Inputs and their version IDs are sealed.

The first real validation found 344 eligible NBA current-season player contexts
and 89 of 90 mapped WNBA playoff contexts. WNBA regular-season discrepancies are
not mixed into playoff inputs. Unmapped players remain excluded. These counts are
a data-validation result, not predictive accuracy or full league availability.

Value policy bk-value-estimate-2 requires a real paired market, observation <=5 min,
decimal odds 1.5-3.5, overround 1.00-1.12, estimated EV >=10%, probability edge >=4
percentage points over the proportional no-vig market, positive baseline EV and
stress EV >=1%. Stress: adverse +/-5% player mean or 2 team points, variance +15%.
The user raised minimum EV from 5% to 10% on 2026-10-23. Pending notification
retries also enforce the current threshold. Historical sealed decisions and the
preregistered model evaluation cohort remain immutable.
Conditional win probability must be 45-80%; player forecasts require >=15 games,
>=20 projected minutes, minutes SD <=8 and participation within the past 7 days.
Unconfirmed injuries/availability remain explicit conditions in every player alert.
PS3838 delayed prices are excluded. Winamax.fr jurisdiction/rules caveats are shown.
At most one alert per player/game and one game-market alert, three total per game.
Each decision/quote snapshot is sealed in bk_value_alerts before Telegram delivery.
Retries require the same current price and an unexpired alert. No wagers are placed.

Protocol bk-advanced-prospective-1 is registered immutably before live forecasts.
Per league, use the first 200 chronological completed games with sealed applied
advanced/base forecasts and a valid observed paired Bet365 moneyline. Both paired
bootstrap 95% CIs of Brier deltas must be below zero versus baseline and no-vig
market to claim improved winner prediction. All candidates, including discards,
qualify; one market observation per game. Props/ROI require a separate future test.
The inspected cohort cannot substantiate a later changed model. Existing v1/v2
research is preserved. Daily four-agent packets contain compact source summaries
so raw quarantine data cannot overflow the review input limit.

Runtime is entirely on the VPS: n8n schedules capture, analysis, research and
Telegram; the VPS collector reads public sources and Supabase stores state/data.
The local PC is used only for development/deployment and may be switched off.

Odds
----
VPS/Tor CuotasAhora reader, exact international bet365 only, full game including OT.
Supported: moneyline, total, spread. Event date, home/away order, league and market
scope checked. Aggregated best-book prices are never treated as Bet365 prices.
Each market has its own observed timestamp and 15-minute expiry. The bookmaker's
own update timestamp is unavailable and explicitly recorded as unknown.
CuotasAhora does not supply player props. A separate anonymous, direct VPS reader
uses the public Winamax.fr NBA/WNBA match pages for paired over/under player lines:
points, rebounds, assists, threes, PRA, PR, PA, RA. The source is explicitly FR;
equivalence to Winamax Spain is not verified. No proxy, login or alternate-domain
retry. An explicit access denial stops the collector until operator review.

Exact league, participants, future visible UTC time and player name are checked.
Calendar tolerance is 20 minutes (the observed source difference was 15 minutes),
stored explicitly; expiry uses the earlier start. Only a unique player in that
game's sealed forecast can become a paper candidate. Unmatched quotes are retained
with a null player_id, not silently assigned. List expansion failures mean partial
coverage; unavailable markets and missing projections never become invented odds.

The official rules reference is dated 2024-08-06 and includes overtime for these
markets. The current rules revision is unconfirmed and remains a candidate caveat.
No automated bets are placed. A once-per-game Telegram price summary is sent in
the last 6 hours, with an explicit Winamax.fr source and no claim of proven edge.
WNBA is read when upcoming games enter the 12-hour window; no individual markets
were visible during the initial manual probe. Check state/quotes for live coverage.

PS3838 public reference prices
-----------------------------
Anonymous Chrome on the VPS reads PS3838's public basketball page and opens each
selected game's additional markets. No login or API credentials are required.
Supported: visible full-game moneyline, spread, total, player points, rebounds,
assists, threes and PRA. English/French player market headings are recognized.
The site explicitly labels anonymous prices as delayed; the delay duration and
bookmaker update timestamp are unknown. All stored observations retain delayed=true,
reference_only=true and source=ps3838_public_delayed. They are excluded from EV,
paper candidates, market benchmarks and executable-odds Telegram summaries, even
when their capture timestamp is fresh. Overtime rules remain unverified.
Exact teams, league and date are required (20-minute calendar tolerance, recorded).
Unmatched player names retain a null player_id. Only a unique player in the same
game's sealed forecasts is mapped. No probabilities or decisions are overwritten.
WNBA shares this reader when games enter the 12-hour window; offered markets still
depend on the public site. A source access denial permanently opens its separate
circuit until operator review. Missing listings receive a 30-minute backoff.
The October 23 anonymous NBA probe returned game and player prices for three games.
Oddschecker was also tested directly from the VPS: Cloudflare HTTP 403 before
login or prices. No credentials were used and no automatic reader was enabled.

Operations
----------
Lynx Basketball - capture: hourly at minute 1, POST /basketball-stats/start.
Lynx Basketball - advanced: starts hourly at minute 11, polls at 16/21/26;
POST /basketball-advanced/start. Reuses unchanged release assets. Source updates are
daily (upstream dependent), not live. Completion/error is checked on following ticks;
operational failures use the existing per-league Telegram deduplication mechanism.
Lynx Basketball - odds/props: poll completed jobs every minute; browser launches
remain limited to one batch per league/source per 5 minutes. Fresh quote ingestion
requests analysis through its authenticated server webhook; the regular five-minute
analysis schedule remains as fallback. This avoids losing the freshness window
while a completed scrape waits for the next poll. Preserve the actual captured_at;
an unchanged price gains freshness only when read again from the source. The time
the book first published or changed the price is independent of our last observation.
Lynx Basketball - ps3838: every 5 minutes offset 4, delayed references only.
Lynx Basketball - analysis: every 5 minutes offset 3, calculations once per game.
Lynx Basketball - research: daily 09:00 UTC; weekly progress and proven improvement.
Lynx Basketball - supervisor: every 10 minutes offset 6, fully hosted in VPS n8n.
Durable checkpoint in bk_state (ALL/supervisor); authenticated recovery actions in
bk_agent_actions with leases, 20-minute cooldown and at most 2 dispatches/hour/task.
Recovery is confirmed only by a newer successful checkpoint, not webhook HTTP 200.
Monitors capture, advanced data, analysis, available game markets and research;
resumes previous-day AI reviews after provider cooldown. No API budget increase.
Only allowed workflow tools can run. It cannot run shell commands, deploy a model,
edit sealed predictions or place bets. Research reuses two compact prior reviews
from Supabase as memory, retaining preregistered statistical gates and provenance.
Persistent failures (>20 minutes) and verified recovery notify Telegram once.
All collectors, models, research and notifications run on the VPS with the PC off.
Pregame context (2026-10-23)
--------------------------
Lynx Basketball - context runs every five minutes on the VPS. Official NBA/WNBA
PDF injury reports are readable from ak-static.cms.nba.com; the league landing
pages returned 403 from this VPS and are not retried. Public RotoWire lineup/news
pages supply explicitly expected/confirmed starters and dated headline metadata.
No subscription analysis, credentials, Tor or IP rotation is used for this feed.
PDF table columns, page continuity, publication time, local game date, matchup,
team and exact player identity must validate. NOT YET SUBMITTED and missing teams
remain unverified. A missing injury listing is not confirmation of participation.
Date-only news cannot supersede a timed official report; unresolved availability
news blocks a value decision. News sentiment never becomes a numeric adjustment.
Context evidence is immutable in bk_context_versions; bk_context_latest retains
the last successful observation. Model revisions change only when the substantive
inputs change, not on every read. bk-context-opportunity-1 preserves its original
advanced forecast ID and creates new sealed rows rather than modifying history.
Known absences have zero projected minutes and cannot generate under picks. A
confirmed starter/bench role recalculates minutes from >=5 matching-role historical
games, using at most ten and bounded to 0.5-1.5 times the original minutes. Means
and variances scale with minutes, retaining combination covariance. Without enough
role history, or when the impact of a recent rotation absence is not modeled, value
alerts are blocked; no unsupported team-probability adjustment is fabricated.
Value alerts require current context <=10 minutes old, a report <=6 hours old,
healthy injury/lineup/news sources, a confirmed quintet, verified participation,
no unresolved news/rotation blocker and a quote observed after the context change.
The 10% EV threshold and all price/model/stress gates remain. The database enforces
the context gate independently, including a match to the latest context revision.
Telegram sends confirmed quintets once, and separate invalidation warnings for
previous value alerts affected by new context. Old decisions remain immutable.
The original preregistered advanced-model 200-game test is unchanged. Context
revisions and their discarded candidates are stored separately by model/version;
no claim of improved accuracy or profitability follows from this integration.
Schema: sql/supabase_basketball_context.sql. Worker: basketball/context_capture.py.
Tests: tests/test_basketball_context.py and tests/basketball_context.test.js.

Winamax low-traffic observation policy (2026-10-24)
------------------------------------------------
Only launch browsers from 15:00 up to 22:00 Europe/Madrid, including DST changes.
NBA and WNBA share a durable Supabase budget: one session per >=30 minutes, at most
14 sessions per Madrid day, up to three games per session, no overlapping jobs.
Each game is revisited at most hourly. League priority rotates between sessions.
The one-minute n8n tick polls our own VPS/database; it is not a Winamax page visit.
Queued worker jobs recheck the window before starting Chrome. The browser closes
at 90 seconds or 22:00, whichever is earlier; process-tree cleanup is bounded at
110 seconds. Errors cause a one-hour shared cooldown; access denials stop capture.
Do not extend quote freshness or reuse afternoon prices for nocturnal value alerts.
An overnight confirmed lineup can therefore have analysis without a fresh prop price.

bk_state/props_publication records each game's inspected absence and first observed
valid player market, with job IDs, times and market names. Failed/partial reads are
not absent markets. First positive reads alone provide no exact publication time.
After >=20 bounded absence-to-presence intervals on >=7 distinct Madrid dates,
checks per game outside the conservative observed window slow to once per two hours.
Sampling still stays within 15:00-22:00 and the shared budget. Telegram reports a
new learned window once; unchanged observations do not generate messages.
History is bounded to 300 games and 45 days per league. No desktop automation runs it.

Player market previews now come from the analysis workflow, once per game/book.
Each includes sealed model projections, both sides' probabilities and EV, the
model's directional forecast and the reason a selection does not qualify. Only
verified paired prices observed within five minutes can be shown. Advanced inputs
are preferred; baseline fallback is labelled and cannot become a value alert.
The raw Winamax price-only message and its pending retries are superseded. Actual
value alerts retain the >=10% EV gate and all other existing eligibility checks.
This is an application supervisor plus the existing four OpenAI reviewers; it is
not this desktop chat running remotely. No local heartbeat is required for operation.
Capture, odds and forecasts run in independent server workflows. Shared scraper
semaphore limits browser concurrency. Import runs separately from the main event loop.
Per-job database leases, idempotent Telegram claims and message_id acknowledgements.
Failed sends retry up to 5 attempts; pregame messages expire at tip-off.
