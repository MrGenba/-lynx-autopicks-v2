Statcast data contract (2026-10-22)

Collector: collectors/statcast.js, embedded into SYNC_MLB_DAILY and SYNC_MILB_DAILY.
Supabase migration: sql/supabase_statcast.sql (not the app's local PostgreSQL).

Current datasets live in bb_statcast_seasons, keyed by player, season, league,
player_type and season_type. MLB uses minors=false; Triple-A uses minors=true
AND hfLevel=AAA. R and POST (F,D,L,W) are separate datasets. The production
models retain their regular-season baseline; postseason data are available for
evaluation, not automatically blended with a small sample.

Each capture replaces every mapped metric, including nulls. Empty CSV values
never become zero. Hard-hit remains a 0..100 percentage. xSLG, barrel counts,
K%, BB%, exit speed, pitch speed, spin and raw export fields are preserved.
BBE and sweet-spot stay null when absent from this export; no denominator or
percentage is invented. The export is aggregate data, not all pitch-level tracking.

The ingest RPC commits the entire dataset and receipt atomically. A sudden loss
of more than half a previously substantial dataset is rejected. Read models use
only the latest successful batch and exclude captures older than 48 hours.
Source URL, league, season, phase, requested cutoff, capture time and batch ID
are preserved in prediction inputs. Exact last observation time remains unknown
when the export does not provide it. The receipt time is not that observation time.

MLB and MiLB SQL views, both app adapters, the manual MiLB bot and the lineup
watcher use these scoped datasets. The young-arms compatibility xwOBA column
is refreshed only from AAA and has its own xwoba_captured_at timestamp.
The app checks all eight source groups every 15 minutes, notifying the private
admin on a failure/state change or recovery with a one-hour cooldown.

The MLB matchup view now joins one pitcher-season aggregate across team stints.
The former join by player/season against per-team rows produced 3882 rows for
2255 games in 2026; it now returns exactly those 2255 games once each. The ERA,
K/9, BB/9 and FIP formulas and underlying gamelogs are preserved.

Historical player_statcast* tables are retained as legacy data and are not the
active Statcast input. player_statcast_catchers was a batting snapshot, not a
defensive tracking feed. Catchers' batting is present among current batters.

Catcher defense extension (2026-10-22)
-----------------------------------
collectors/catcher_defense.js and sql/supabase_catcher_defense.sql add three
independently timestamped MLB sources, refreshed with the 13:00 Madrid MLB sync:
  framing: Regular, all catchers (minPitches=0); runs, pitches, shadow strike %.
  blocking: Regular, all catchers with >=1 opportunity (n=1), across team stints;
    runs, opportunities, actual/expected PB+WP and blocks above average.
  poptime: season export with min2b=min3b=0; arm strength MPH, exchange and pop
    times in seconds, and attempts to second/third. Phase is SOURCE_DEFAULT
    because this source exposes no game-type selector; never silently labeled R.

Framing pct_tot is a fraction converted to 0..100; negative run values and true
zeros are retained. Missing measurements remain null. Raw CSV fields are stored.
bb_catcher_defense_current accepts only the latest complete batch per source
within 48 hours. Source observation cutoff remains unknown, distinct from capture.
Atomic ingest rejects duplicate players, invalid ranges and abrupt large losses.

In full_lineup MLB evaluations, the actual starting catcher is identified from
the official boxscore (position 2 in the confirmed nine, not roster position/DH).
Fresh, correctly scoped defense metrics and opportunity counts enter the saved
prediction evidence under catcher_defense, with missing groups explicit. They
are for prospective evaluation; no unvalidated probability coefficients are added.
The 15-minute health monitor alerts the private admin on failure or recovery.

LMB tracking coverage
--------------------
The same daily job checks the most recent completed game at every LMB venue
recorded in Supabase, via the official MLB StatsAPI feed. It counts actual pitch
speed, spin, exit velocity and launch-angle measurements, not empty pitchData
objects or scoring coordinates. bb_tracking_coverage retains the per-game URLs
and counts; bb_tracking_coverage_health exposes sample size and freshness.
The first sample: 21 venues, 6196 pitches, 1193 balls in play; zero measurements
for those four tracking fields. This is sampled public coverage, not proof that
clubs lack private Trackman data. No LMB Statcast values are synthesized or copied
from MLB. LMB conventional statistics continue through the existing sync.
Newly detected public tracking generates an admin alert for coverage validation;
unchanged unavailability stays quiet. A licensed LMB/Trackman export is needed
to populate those tracking metrics when the public feed omits them.
